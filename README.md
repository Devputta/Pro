## Design Philosophy

This project intentionally avoids the typical AI-generated website aesthetic.

### The interface avoids

* generic SaaS templates
* purple-to-blue gradients
* excessive glassmorphism
* giant centered hero sections
* repetitive three-card layouts
* meaningless statistics
* fake testimonials
* unnecessary animations
* excessive rounded containers
* decorative elements without a purpose

### Instead, it focuses on

* clear hierarchy
* useful interaction
* strong typography
* responsive layouts
* practical navigation
* restrained visual language
* intentional spacing
* human-written copy
* accessibility
* maintainable implementation

> **The goal isn't to make the website look "AI-powered."
> The goal is to make it look thoughtfully built.**

## Web + Mobile

The portfolio is designed as a responsive experience rather than a desktop page that happens to shrink on mobile.

### Desktop

* expanded navigation
* larger project presentation
* comfortable reading width
* full documentation navigation

### Mobile

* simplified navigation
* touch-friendly controls
* focused content hierarchy
* responsive typography
* no unnecessary horizontal scrolling
* mobile-specific layout decisions

The mobile experience is treated as a first-class interface.

## Development Principles

### 1. Build for real use

Every feature should solve an actual problem.

### 2. Keep the architecture understandable

Prefer a small number of clear abstractions over unnecessary complexity.

### 3. Preserve working functionality

Changes should improve the project without unnecessarily rewriting stable parts.

### 4. Mobile matters

Every major UI change should be checked on both desktop and mobile.

### 5. No fake product claims

No fabricated:

* user numbers
* customer logos
* testimonials
* ratings
* performance statistics

### 6. Security by default

Secrets, API keys and private credentials should never be committed to the repository.

## Security

Security guidelines are documented in:

```text
docs/security.md
```

The project follows basic secure-development practices including:

* no committed secrets
* environment-based configuration
* dependency awareness
* safe input handling
* secure deployment configuration
* responsible vulnerability reporting

If you discover a security issue, please avoid publicly exposing exploit details before the issue can be addressed.
